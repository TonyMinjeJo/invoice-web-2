# 견적서 웹 뷰어 개발 로드맵

> 기준일: 2026-10-24 · 원본 요구사항: `docs/PRD.md` · 지침: `CLAUDE.md`
> 완료된 작업은 `docs:update-roadmap` 스킬이 `- [x]`로 갱신합니다.

## 1. 프로젝트 개요 및 목표

노션 데이터베이스에 입력한 견적서를 클라이언트가 발행자에게 받은 공유 링크로 웹에서 확인하고 PDF로 내려받는 **조회 전용 MVP**입니다. 입력·수정은 노션에서만 하며, 로그인, 발행자용 관리 화면, 견적 승인·서명, 이메일 발송은 MVP 범위에서 제외합니다. 부가세는 10%로 계산해 표시합니다.

## 7. 미결정 사항 (Open Questions)

추측으로 채우지 않고 사용자 확인이 필요한 항목입니다.

- **Q1. PRD 본문 부재**: `docs/PRD.md`는 PRD를 생성하는 프롬프트만 담고 있으며, 실제 기능 명세, 메뉴 구조, 페이지별 상세, 데이터 모델이 없습니다. 이 로드맵은 PRD의 확정 전제만 근거로 작성했습니다.
- **Q2. 견적서 식별 방식**: 공유 링크에 노션 페이지 ID를 쓸지, 별도 공유용 slug 속성을 둘지, 공개 여부 체크 속성이 필요한지 정해야 합니다. 추측 가능한 ID를 쓰면 타인 견적서 노출 위험이 있습니다.
- **Q3. PDF 생성 방식**: 서버에서 `@react-pdf/renderer`로 생성할지, 브라우저 인쇄 기능을 쓸지 정해야 합니다.
- **Q4. 견적서 필드 목록**: 발행자·수신자 정보, 항목 필드(품명, 수량, 단가, 금액), 비고, 통화 단위(원화 여부)를 확정해야 합니다.
- **Q5. 금액 규칙**: 부가세 반올림 방식(원 단위 절사, 반올림, 올림), 할인 항목 유무, 항목 금액을 노션 수식으로 계산할지 앱에서 계산할지 정해야 합니다.
- **Q6. 견적서 상태**: 임시 저장본과 발행본을 구분하는 상태 속성이 필요한지, 임시본 링크 노출을 어떻게 막을지 정해야 합니다.
- **Q7. 검색 노출과 링크 수명**: 견적서 페이지를 검색엔진에 노출할지(noindex 여부), 공유 링크에 만료 기간을 둘지 정해야 합니다.
- **Q8. MVP 이후 기능 목록**: PRD의 "MVP 이후 기능" 항목이 아직 없습니다.
- **Q9. 테스트 도입**: 현재 테스트 러너가 없습니다. 금액 계산 단위 테스트를 위해 도입할지 정해야 합니다.
- **Q10. 배포 환경과 도메인**: 호스팅 서비스와 도메인을 정해야 합니다. PRD는 인프라를 다루지 않습니다.
- **Q11. Next.js 버전**: CLAUDE.md는 15.5.3 고정이지만 PRD는 최신 패치 15.5.28을 언급합니다. 어느 쪽으로 할지 정해야 합니다.
- **Q12. 반응형과 언어 범위**: PRD에 반응형과 다국어 요구가 없습니다. 모바일 대응 필수 여부와 한국어 단일 언어 여부를 확인해야 합니다.
- **Q13. 데이터 반영 지연**: 노션에서 수정한 내용이 웹에 반영되기까지 허용되는 시간을 정해야 합니다 (캐시 주기 결정).
- **Q14. 한글 폰트**: PDF에 사용할 폰트 파일과 라이선스를 정해야 합니다.
- **Q15. PDF 페이지 구성**: 항목이 많을 때 여러 페이지로 나눌지, A4 한 장에 맞출지 정해야 합니다.
- **Q16. 홈과 잘못된 링크 화면**: 홈 `/`에 안내 문구를 둘지 404로 둘지, 잘못된 링크에 안내 화면을 보여줄지 정해야 합니다.

## 9. 비기능 요구사항

PRD에 명시된 항목만 기재합니다.

- **조회 전용**: 웹에서 견적서를 수정하는 경로를 만들지 않습니다 (R-01).
- **로그인 없음**: 공유 링크만으로 접근합니다 (R-02).
- **부가세 10%**: 모든 금액 표시에 동일하게 적용합니다 (R-04).
- **언어**: 현재 `lang="ko"` 설정을 따릅니다 (Q12에서 확정).

PRD에 없는 성능 목표, 접근성 기준, SEO 요구는 포함하지 않았습니다. 필요하면 Q7, Q12에서 확정한 뒤 추가합니다.

## 10. 검증 방법

- **각 페이즈 종료 시**: `npm run check-all` (typecheck, lint, format:check)과 `npm run build` 통과를 DoD에 포함합니다.
- **수동 검증**: 샘플 견적서 3건으로 조회, 금액, PDF 다운로드를 확인합니다. 로컬은 `npm run dev`로 확인합니다.
- **최종 검증**: Phase 4의 시나리오 검증(4-1)과 운영 스모크 테스트(4-7)를 완료 기준으로 사용합니다.
