# 노션 견적서 웹 뷰어 개발 로드맵

노션에 입력한 견적서를 클라이언트가 공유 링크로 웹에서 확인하고 PDF로 내려받는 MVP 웹 애플리케이션입니다.

## 개요

노션 견적서 웹 뷰어는 견적서를 발행하는 1인 사업자와 그 견적서를 받는 클라이언트를 위한 **견적서 조회 및 PDF 다운로드 도구**로 다음 기능을 제공합니다:

- **노션 기반 견적서 조회**: 노션 데이터베이스에 입력된 견적 항목, 금액, 수신자 정보를 웹 화면으로 표시 (웹은 조회 전용)
- **공유 링크 접근**: 발행자가 전달한 링크로 로그인 없이 견적서 확인
- **PDF 다운로드**: 견적서 화면에서 PDF 파일로 저장 (부가세 10% 포함 금액 표시)

### MVP 전제 (변경 금지)

- 견적서 원본은 **노션 데이터베이스**이며, 입력·수정은 노션에서만 한다.
- 웹은 **조회 전용**이다. 발행자용 웹 관리 화면은 만들지 않는다.
- 클라이언트는 **공유 링크**로 접속하며 **로그인은 MVP에 포함하지 않는다.**
- 부가세는 **10%**로 계산해 표시한다.
- 견적 승인·서명, 이메일 발송은 MVP에서 제외한다.

## 개발 워크플로우

1. **작업 계획**
   - 기존 코드베이스를 확인하고 현재 상태를 파악한다.
   - 새로운 작업을 포함하도록 `docs/ROADMAP2.md`를 업데이트한다.
   - 우선순위 작업은 마지막 완료된 작업 다음에 삽입한다.

2. **작업 생성**
   - 작업 시작 시 `docs/tasks/` 디렉토리에 `XXX-description.md` 파일을 만든다 (예: `002-routes-skeleton.md`).
   - 고수준 명세, 관련 파일, 수락 기준, 구현 단계를 포함한다.
   - 노션 API 연동과 비즈니스 로직 작업에는 반드시 **"## 테스트 체크리스트"** 섹션을 포함한다 (Playwright MCP 시나리오).
   - 테스트 체크리스트는 `TC-XXX-NN` 형식으로 정상, 예외, 경계, 회귀 시나리오를 모두 포함하고 아래 최소 수량을 충족한다.
     - 정상 1개 이상, 예외 2개 이상, 경계 1개 이상, 회귀 1개 이상
     - 네트워크 확인 시나리오 1개 이상 (노션 API 상태 코드, 응답 필드)
     - UI가 포함된 경우 모바일 뷰포트 시나리오 1개 이상

3. **작업 구현**
   - 작업 파일의 명세를 따른다.
   - API 연동 및 비즈니스 로직 구현 시 Playwright MCP로 테스트한다 (아래 "테스트 실행 절차" 1~6단계를 순서대로 수행).
   - 각 단계 후 작업 파일의 진행 상황을 업데이트한다.
   - 실패 시 원인을 구현 버그, 시나리오 오류, 환경 문제로 분류한다. 구현 버그는 수정 후 해당 시나리오부터 재실행한다.
   - 구현 완료 후 `npm run check-all`, `npm run build`를 통과시키고 Playwright MCP로 E2E 테스트를 실행한다.
   - 각 Task 완료 후 중단하고 추가 지시를 기다린다.

4. **로드맵 업데이트**
   - 완료된 작업을 ✅로 표시하고, Phase 내 모든 Task가 완료되면 Phase 제목에도 ✅를 붙인다.

## 테스트 실행 절차 (Playwright MCP)

API 연동, 데이터 변환, 계산, 상태 전환 등 비즈니스 로직 Task는 아래 6단계를 **순서대로** 수행하고, 각 단계의 결과를 작업 파일에 기록합니다.

**1단계: 테스트 범위 분석**

- 검증 대상 목록 작성: 노션 API 호출, 데이터 변환 규칙, 계산식, 상태 전이(임시 / 발행), 노출 조건(공유 링크 접근)
- 각 대상의 입력과 기대 출력 정의
- 외부 의존성(노션 API)의 성공, 실패, 지연 응답 시나리오 식별

**2단계: 테스트 시나리오 설계**

- 시나리오마다 다음을 명시한다.
  - 사전 조건: 노션 데이터 상태, 환경변수, 로그인 여부 (MVP는 로그인 없음)
  - 단계: 사용자 행동 순서
  - 기대 결과: 화면, 네트워크, 콘솔 각각의 기대값 (수치는 단위까지 명시)

**3단계: 테스트 환경 준비**

- 개발 서버(`npm run dev`) 실행 후 대상 URL 확인
- 테스트용 노션 데이터 준비: 정상, 필수 값 누락, 임시 상태, 항목 0개, 항목 다수 (식별자 기록)
- 외부 API 실패 재현 방법 기록 (예: 잘못된 API 키, 존재하지 않는 DB ID)
- 실제 고객 정보는 테스트 데이터로 사용하지 않는다

**4단계: Playwright MCP 실행**
시나리오마다 다음 도구 순서로 실행합니다.

1. `browser_navigate`: 대상 공유 링크 진입
2. `browser_wait_for`: 로딩 완료 또는 핵심 텍스트 출현 대기
3. `browser_snapshot`: 화면 구조 확인 (제목, 표, 버튼 존재 여부, 금액 텍스트 추출)
4. `browser_click`, `browser_fill_form`, `browser_press_key`: 사용자 행동 재현 (PDF 버튼, 키보드 탐색)
5. `browser_network_requests`: 노션 API 또는 PDF 라우트의 호출 횟수, 상태 코드, 응답 필드 확인
6. `browser_console_messages`: 에러 로그 없음 확인
7. `browser_take_screenshot`: 주요 상태 증빙 저장
8. 모바일 시나리오는 `browser_resize`로 390×844 뷰포트에서 같은 절차 반복

**5단계: 결과 검증**

- 기대 결과와 실제 결과를 항목별로 대조 (통과 / 실패)
- 수치(공급가액, 부가세, 총액)는 입력 항목으로 직접 계산한 값과 비교
- 실패 시 원인 분류
  - 구현 버그: 수정 후 해당 시나리오부터 재실행
  - 시나리오 오류: 시나리오를 고친 뒤 재실행
  - 환경 문제: 재현 조건을 기록하고 보류 표시
- 같은 시나리오를 최소 2회 실행해 결과가 일관적인지 확인 (비동기, 캐시 문제 탐지)

**6단계: 결과 기록 및 완료 판정**

- 작업 파일의 "## 테스트 체크리스트"에 시나리오별 결과(✅ / ❌ / 보류)와 실행 일시 기록
- 정상, 예외, 경계 시나리오가 모두 ✅여야 Task를 완료로 표시
- 회귀 테스트 통과 후 `npm run check-all`, `npm run build` 실행
- 완료 후 중단하고 추가 지시를 기다린다

## 기술 스택

- **프레임워크**: Next.js 15.5.3 (App Router, Turbopack), React 19.1.0, TypeScript 5
- **스타일링**: TailwindCSS v4, shadcn/ui (new-york), Radix UI, Lucide Icons
- **노션 연동**: `@notionhq/client` (Phase 3에서 설치, npm 최신 5.28.0 기준 검토)
- **PDF 생성**: `@react-pdf/renderer` (Phase 3에서 설치, npm 최신 4.9.0 기준 검토, Q3 확정 후 최종 결정)
- **데이터 검증**: Zod (노션 응답 검증용), React Hook Form은 MVP에 입력 폼이 없어 현재는 사용하지 않음
- **품질 도구**: ESLint, Prettier, Husky, lint-staged
- **E2E 테스트**: Playwright MCP

## 비기능 요구사항

- 모바일 포함 반응형 화면, 가로 스크롤 없음 (TC-005-03, TC-015-01)
- 견적서 화면과 PDF의 금액 일치 (TC-010-04, TC-012-02)
- 노션 API 키는 서버에서만 사용 (TC-008-04)
- 로그인 없이 공유 링크로 접근 가능 (TC-010-02)

## 검증 방법

- 각 Phase 종료 시 `npm run check-all`, `npm run build` 통과를 완료 기준에 포함한다.
- API 연동 및 비즈니스 로직 Task는 "테스트 실행 절차" 1~6단계를 모두 수행하고, 정상, 예외, 경계, 회귀 시나리오가 모두 ✅여야 완료로 표시한다.
- 실패한 시나리오는 원인을 구현 버그, 시나리오 오류, 환경 문제로 분류해 기록한다.
- Phase 4에서 운영 URL 기준 E2E 테스트를 한 번 더 수행한다.
