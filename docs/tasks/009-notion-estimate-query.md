# Task 009: 노션 견적서 조회 및 데이터 정규화

## 목표

공유 식별자(노션 페이지 ID)로 견적서 한 건을 노션에서 읽고, 기존 `Quote` 타입으로 바꾼다. 웹은 노션에 쓰지 않는다.

## 변경 파일

| 파일                                | 상태 | 내용                                                            |
| ----------------------------------- | ---- | --------------------------------------------------------------- |
| `src/lib/notion/estimate-schema.ts` | 생성 | 속성 읽기 함수, Zod 검증, 헤더와 항목 매핑                      |
| `src/lib/notion/get-estimate.ts`    | 생성 | 식별자 정규화, 데이터 소스 찾기, 페이지 조회, 항목 페이지네이션 |

## 설계 결정

- 항목 DB의 데이터 소스 ID는 환경변수로 받지 않고 `invoices`의 `항목` 관계 속성 설정(`relation.data_source_id`)에서 읽는다.
- 견적서 DB에 속하지 않는 페이지는 `parent.data_source_id`로 걸러내 `notFound`로 돌려준다.
- 항목 조회는 `dataSources.query`에 `invoices` 관계 `contains` 필터를 걸고, 100개 단위로 `start_cursor`를 따라간다.
- 항목 정제 규칙은 003 문서를 따른다. 빈 행은 버리고, 일부만 비어 있으면 검증 실패로 본다. 사용자 확인 필요 (calculate.ts와 충돌).
- 상태: 현재 코드는 옵션 이름 `발행`만 `issued`로 본다. 실제 노션 옵션에는 `발행`이 없다 (아래 참고).

## 실연결 검증 (2026-10-27, 읽기 전용)

- 견적서 DB 쿼리: 1건 (`INV-2026-001`, 상태 `대기`).
- `getEstimate(페이지 ID)`: `ok`. 헤더 필드와 항목 3건을 읽었다.
  - 웹사이트 디자인 1 × 3,000,000 / 명함 디자인 100 × 10,000 / 로고 제작 2 × 500,000
  - 계산: 공급가액 5,000,000, 부가세 500,000, 총액 5,500,000
- 하이픈 없는 대문자 식별자도 같은 견적서로 조회됨.
- 존재하지 않는 식별자(`000...0`): 노션 404 → `notFound`.
- 형식이 틀린 식별자: 노션 호출 없이 `notFound`.
- 호출 순서: DB 조회, 데이터 소스 조회, 페이지 조회, 항목 쿼리 (총 4회). 데이터 소스 ID는 캐시되어 두 번째 조회부터 생략됨.

## 발견한 문제

1. **상태 옵션 불일치 (중요)**: 실제 `상태` 속성 옵션은 `대기`, `거절`, `승인`이다. `발행`이 없다. 지금 코드는 `발행`만 issued로 보므로, `승인`인 견적서도 draft로 처리되어 공유 링크에서 열리지 않는다. 어느 옵션을 issued로 볼지 결정이 필요하다.
2. 노션 `총 금액`(5,000,000)은 공급가액과 같고, 총액(5,500,000)과 다르다. 화면 계산에는 쓰지 않으므로 영향은 없지만 의미를 확인해야 한다.

## 단위 검증 (2026-10-27, 임시 스크립트, 실행 후 삭제)

샘플 노션 응답을 `mapItem`, `mapInvoiceFields`에 넣어 확인했다. 식별자 정규화는 `get-estimate.ts`가 `server-only`라 같은 규칙을 스크립트에 옮겨 확인했다.

- 정상 항목 → ok, 빈 행(항목명·수량·단가 모두 없음) → skip
- 일부만 채운 행 → invalid (`quantity`), 항목명 없음 → invalid (`name`)
- 음수 수량 → invalid, 소수 수량 → invalid
- 정상 헤더 → ok (발행일 시간 부분 제거), 상태 `대기` → draft, `발행` → issued
- 견적서 번호 누락 → invalid (`quoteNumber`), 발행일 누락 → invalid (`issueDate`)
- 총 금액 없음 → ok (null 허용)
- 하이픈 포함 식별자 정규화 통과, 형식 오류 식별자 → null
- 결과: 13/13 통과

## 정제 규칙 결정

사용자 결정 전까지 003 규칙을 따른다. 빈 행은 버리고, 일부만 비어 있는 행은 검증 실패로 `notFound`가 아닌 `invalid`로 돌려준다. `calculate.ts`의 제외 로직은 그대로 두었다. 두 규칙이 다르므로 이 충돌은 사용자 결정이 필요하다.
