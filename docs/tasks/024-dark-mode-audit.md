# Task 024: 다크 모드 전 화면 점검과 대비 보완

## 명세

- 신규 구현이 아니라 점검과 보완이다. `next-themes`(`defaultTheme="system"`), 헤더 토글(라이트·다크·시스템), `.dark` 토큰은 그대로 쓴다. 관리자 헤더의 `ThemeToggle`은 Task 019에서 이미 두었다.
- `globals.css`에 `color-scheme`을 추가했다(`:root` light, `.dark` dark). 참고: `next-themes`가 `<html>`의 인라인 `color-scheme`을 이미 설정하고 있어 계산값은 변하지 않는다. CSS 선언은 JS 이전의 첫 페인트와 명세 충족을 위한 보강이다.
- 정식 대비 측정: 화면의 모든 가시 텍스트(요소별 글자색과 겹친 배경 합성, 불투명도 반영)와 입력·버튼·Badge 경계를 Playwright에서 계산했다. 본문 기준은 4.5:1(큰 글자 3:1), 경계는 3:1. 측정 스크립트는 저장소 밖 임시 파일이다.
- PDF 색(`estimate-document.tsx`)은 바꾸지 않았다.

- 경고 문구(`text-destructive`)와 Badge 문구(거절, 정보 누락, 만료됨 포함)는 위 측정에 포함되어 라이트·다크 모두 4.5:1 이상이다.
- **발견한 문제**: 입력 필드(`Input`) 경계가 라이트 1.26:1, 다크 1.47:1로 UI 요소 3:1(WCAG 1.4.11)에 미달했다. 텍스트 라벨이 있는 버튼과 Badge의 경계는 식별에 필수가 아니어서 대상에서 제외했다.
- **보완**: `globals.css` 토큰만 수정. `--input` 라이트 `oklch(0.922 0 0)` → `oklch(0.62 0 0)`(3.64:1), 다크 `oklch(1 0 0 / 15%)` → `oklch(1 0 0 / 40%)`(3.77:1). 컴포넌트에는 색을 직접 쓰지 않았다. 부수 효과: 다크의 outline 버튼 경계와 입력 배경 틴트(`dark:bg-input/30`)가 조금 밝아졌고, 라이트의 체크박스·셀렉트 경계가 진해졌다(현재 화면에는 해당 컴포넌트 없음).
