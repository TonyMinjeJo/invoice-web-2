# 견적서 웹 뷰어 고도화 로드맵

> 기준일: 2026-10-28 · 기준 문서: `docs/PRD.md`, `docs/roadmaps/ROADMAP2_v1.md`, `docs/post-mvp-features.md` · 지침: `CLAUDE.md`, `shrimp-rules.md`
> MVP(Phase 1~4, Task 001~017)는 완료되어 운영 중입니다. 이 문서는 MVP 이후 고도화 작업만 다룹니다.

## 개요

견적서 웹 뷰어는 발행자가 노션에 작성한 견적서를 클라이언트가 공유 링크로 확인하고 PDF로 내려받는 도구입니다. 고도화의 목표는 발행자가 **관리자 화면에서 견적서를 모아 보고, 클라이언트에게 보낼 링크를 바로 복사**하게 하고, **다크 모드를 전 화면에서 점검**하는 것입니다.

- **관리자 견적서 목록**: 관리자 레이아웃에서 노션 견적서 목록을 봅니다 (읽기 전용).
- **공유 링크 복사**: 목록의 행에서 클라이언트에게 보낼 공유 링크를 복사합니다.
- **다크 모드 고도화**: 이미 구현된 테마 전환을 전 화면에서 점검하고, WCAG AA 대비를 정식으로 측정해 보완합니다.

## 고도화 전제 변경

MVP 전제 중 아래 항목이 고도화에서 바뀝니다. 원래 PRD 전제는 MVP 기준으로 남기고, 변경 내역은 Task 018에서 PRD와 규칙 문서에 별도 항목으로 추가합니다.

| 항목      | MVP 전제                  | 고도화 전제                                     | 이유                                                                                   |
| --------- | ------------------------- | ----------------------------------------------- | -------------------------------------------------------------------------------------- |
| 관리 화면 | 발행자용 관리 화면 제외   | 읽기 전용 견적서 목록 포함                      | 요구사항 (목록, 링크 복사)                                                             |
| 로그인    | 로그인 없음               | 클라이언트 로그인 없음 유지, 관리자 로그인 추가 | 목록은 모든 견적서를 보여줍니다. 인증 없이 열면 공유 링크 보안 모델(R-03)이 무너집니다 |
| 웹 쓰기   | 조회 전용                 | 조회 전용 유지 (관리자 화면도 편집 없음)        | 원본은 노션입니다 (R-01, R-02)                                                         |
| 다크 모드 | 테마 전환 구현 (Task 001) | 전 화면 점검과 대비 보완 (Task 024)             | 기존 구현 유지, 검증 범위 확대                                                         |

**확인 필요**: 관리자 로그인은 요구사항에 명시되지 않았지만, 목록 노출을 막으려면 필수라고 판단해 추가했습니다. 방식은 G1에서 확정합니다.

`shrimp-rules.md`의 §3(인증 금지), §5-6(폼 금지), §10(금지 사항)은 MVP 규칙입니다. Task 018에서 고도화 규칙으로 바꾸기 전에는 인증 구현이 규칙 위반이므로, Task 018이 선행 조건입니다.

## 테스트 실행 절차 (Playwright MCP)

MVP 절차(`docs/roadmaps/ROADMAP2_v1.md`)를 따르고, 고도화에서 추가되는 규칙만 아래에 적습니다.

1. **범위 분석**: 노션 호출, 상태 판정, 인증 게이트, 클립보드 복사, 테마 전환을 검증 대상으로 적습니다.
2. **시나리오 설계**: 사전 조건에 **"로그인 상태"** 또는 **"비로그인 상태(쿠키 없는 새 컨텍스트)"**를 명시합니다.
3. **환경 준비**: 관리자 비밀번호와 세션 시크릿은 `.env.local`에만 둡니다. 테스트 데이터는 승인, 대기, 거절, 유효기간 만료, 정보 누락, 0건, 101건 상태를 식별자와 함께 기록합니다.
4. **Playwright MCP 실행**: `browser_navigate` → `browser_wait_for` → `browser_snapshot` → `browser_click` / `browser_fill_form` → `browser_network_requests` → `browser_console_messages` → `browser_take_screenshot` 순서로 실행합니다. 모바일은 `browser_resize`로 390×844에서 반복합니다.
5. **결과 검증**: 기대값과 실제값을 항목별로 대조합니다. 금액은 입력값으로 직접 계산한 값과 비교합니다. 같은 시나리오는 2회 실행해 일관성을 확인합니다.
6. **기록과 판정**: 작업 파일의 "## 테스트 체크리스트"에 ✅ / ❌ / 보류와 실행 일시를 적습니다. 정상, 예외, 경계 시나리오가 모두 ✅여야 완료로 표시합니다.

**고도화 추가 규칙**

- **노션 호출 확인**: 노션 호출은 서버에서 일어나므로 브라우저의 `browser_network_requests`에는 보이지 않습니다. 테스트용 `NOTION_BASE_URL`로 가짜 노션 서버를 띄우고 그 요청 로그로 확인합니다 (MVP TC-013 방식).
- **클립보드**: `browser_evaluate`로 `navigator.clipboard.readText()`를 호출해 확인합니다. 권한 거부로 실패하면 환경 문제로 분류합니다.
- **쿠키 속성**: `httpOnly`, `secure`, `sameSite`, `path`는 `browser_run_code_unsafe`로 컨텍스트의 쿠키 목록을 읽어 확인합니다.

## 기술 결정 (고도화)

- **인증**: 외부 인증 서비스와 새 패키지를 추가하지 않습니다. 세션 서명은 Node `crypto`(HMAC-SHA256)로 직접 구현합니다. G1에서 Google 로그인으로 바꾸면 이 절을 갱신합니다.
- **폼**: 관리자 로그인은 입력이 하나뿐이므로 네이티브 `<form>`과 Server Action을 씁니다. `react-hook-form`은 추가하지 않습니다.
- **라우트**: 관리자 화면은 `src/app/admin/`에 두고, 공개 `src/app/estimate/`와 섞지 않습니다. 라우트 그룹은 쓰지 않습니다.
- **데이터 흐름**: 관리자 목록도 노션 → 서버 함수 → 서버 컴포넌트 흐름을 따릅니다. 브라우저는 노션을 직접 호출하지 않습니다.
- **캐시**: 공개 조회는 Q5 확정대로 1시간 캐시를 유지합니다. 관리자 목록은 캐시하지 않습니다 (G3). 인증이 필요한 페이지는 정적 캐시로 굳지 않도록 동적으로 렌더링합니다.
- **테마**: `next-themes`를 그대로 씁니다. 테마 라이브러리는 추가하지 않습니다.
- **PDF 색**: 테마와 무관하게 고정합니다 (인쇄 기준).
- **상태 이름**: 노션 `상태` 옵션 `승인`이 발행 상태이고, 그 밖의 값은 임시입니다 (코드와 공유 가이드 기준). ROADMAP2_v1의 '발행' 표기는 과거 표기입니다.
- **새 의존성**: 없습니다. 필요해지면 이 절에 먼저 적습니다 (`shrimp-rules.md` §6-3).

## 비기능 요구사항
